Panoramica

rid è un editor di testo minimale che gira direttamente nel terminale, scritto in C99. Caratteristiche principali:

  • Modalità terminale raw (nessun buffering di riga)
  • Rendering con sequenze di escape ANSI
  • Supporto completo per UTF-8 (caratteri multi-byte come è, ñ, 日, 🚀)
  • Scrolling verticale e orizzontale
  • Inserimento, cancellazione e salvataggio su file

Architettura e flusso dati

Il cuore dell'editor è un ciclo read → process → render in main.c:

┌─────────────────────────────────────────────────┐
│ main loop │
│ │
│ 1. term_read_key() ──▶ legge un tasto │
│ 2. dispatch ──▶ modifica lo stato │
│ 3. editor_refresh_screen() ──▶ ridisegna tutto │
│ │
│ Ripeti finché l'utente non preme Ctrl+Q │
└─────────────────────────────────────────────────┘

Flusso in dettaglio

  1. Input — term_read_key() legge byte da stdin. Se il byte iniziale è ≥ 0x80 (multi-byte UTF-8), legge i byte di continuazione e decodifica il codepoint.
  2. Dispatch — main.c decide cosa fare in base al tasto:
    • Ctrl+Q → esci
    • Ctrl+S → salva e esci
    • Frecce → editor_move_cursor()
    • Backspace → editor_del_char()
    • Enter → editor_insert_newline()
    • Carattere stampabile → editor_insert_char()
  3. Rendering — editor_refresh_screen() :
    • Chiama editor_scroll() per aggiornare gli offset
    • Costruisce l'intero frame in un abuf (buffer dinamico)
    • Scrive il buffer su stdout con una singola write() (zero-flicker)

Come estendere il progetto

1. Syntax Highlighting (evidenziazione sintassi)

Dove intervenire: editor_draw_rows() in editor_conf.c

Idea: Prima di scrivere una riga nel buffer con ab_append(), analizza il contenuto e inserisci sequenze di escape ANSI colorate attorno alle keyword.

// Esempio: colorare una keyword in giallo
ab_append(ab, "\x1b[33m", 5); // inizio giallo
ab_append(ab, "return", 6); // keyword
ab_append(ab, "\x1b[0m", 4); // reset colore

Struttura suggerita:

  • Crea un nuovo modulo syntax.h/c
  • Definisci una struct per i linguaggi (estensioni file, keyword, commenti)
  • In editor_draw_rows() chiama una funzione syntax_highlight_row() che restituisca la riga colorata

Aggiungi al makefile:

SRCS = main.c abuf.c term.c rrow.c editor_conf.c utf8.c syntax.c

2. Barra di stato (status bar)

Dove intervenire: editor_draw_rows() o editor_refresh_screen() in editor_conf.c

Idea: Riserva l'ultima riga (o le ultime 2) della finestra per mostrare informazioni:

nome_file.c | Righe: 42 | Pos: 10,5 | UTF-8
  • Riduci window_height di 1 in editor_init() per riservare lo spazio
  • Disegna la barra con colori invertiti: \x1b[7m (inversione) e \x1b[m (reset)

3. Ricerca nel testo (Ctrl+F)

Dove intervenire: main.c (nuovo comando) + nuova funzione in editor_conf.c

Passi:

  1. Cattura Ctrl+F nel loop principale
  2. Mostra un prompt nella barra di stato (o nell'ultima riga)
  3. Leggi la query carattere per carattere
  4. Scansiona ogni rrow cercando la sottostringa (attenzione: lavora sui byte, dato che UTF-8 è comparabile byte-a-byte)
  5. Se trovata, sposta il cursore alla posizione convertendo il byte offset in codepoint index con utf8_cp_index()

4. Undo/Redo

Idea: Implementa uno stack di operazioni.

// nuovo file: undo.h
enum op_type { OP_INSERT_CHAR, OP_DEL_CHAR, OP_INSERT_LINE, OP_DEL_LINE };
struct edit_op {
enum op_type type;
int row, col; // Posizione dell'operazione
uint32_t codepoint; // Carattere coinvolto (per insert/delete)
char *line_content; // Contenuto riga (per operazioni su righe intere)
};
  • Ogni volta che editor_insert_char(), editor_del_char() ecc. vengono chiamate, pusha l'operazione sullo stack
  • Ctrl+Z → pop dallo stack e applica l'operazione inversa

5. Numeri di riga

Dove intervenire: editor_draw_rows() in editor_conf.c

Idea: Prima del contenuto di ogni riga, stampa il numero:

char linenum[16];
int numlen = snprintf(linenum, sizeof(linenum), "%4d ", filerow + 1);
ab_append(ab, "\x1b[90m", 5); // grigio
ab_append(ab, linenum, numlen);
ab_append(ab, "\x1b[0m", 4); // reset
  • Aggiusta coloff per tenere conto della larghezza dei numeri di riga

6. Supporto per Tab (<tt>\t</tt>)

Dove intervenire: editor_draw_rows() e/o rrow.c

Idea: Quando incontri \t nei dati, rendilo come N spazi (tipicamente 4 o 8). Puoi farlo al momento del rendering in editor_draw_rows() senza modificare i dati in memoria.

Guida alla codifica UTF-8

Cos'è UTF-8?

UTF-8 è un sistema per rappresentare tutti i caratteri del mondo (Unicode) usando sequenze di 1–4 byte. È il formato dominante su internet e nei sistemi Linux.

La cosa geniale di UTF-8 è che è retrocompatibile con ASCII: i primi 128 caratteri (lettere inglesi, numeri, punteggiatura) usano esattamente un byte, identico ad ASCII.

Come funziona la codifica

Il primo byte di ogni carattere indica quanti byte totali occupa:

Primo byte (binario) Byte totali Range Unicode Esempio
0xxxxxxx 1 U+0000 – U+007F A = 0x41
110xxxxx 2 U+0080 – U+07FF è = 0xC3 0xA8
1110xxxx 3 U+0800 – U+FFFF 日 = 0xE6 0x97 0xA5
11110xxx 4 U+10000 – U+10FFFF 🚀 = 0xF0 0x9F 0x9A 0x80

I byte di continuazione iniziano sempre con 10xxxxxx.

Esempio pratico: codificare <tt>è</tt> (U+00E8)

Il codepoint di è è U+00E8 (232 in decimale, 0xE8 in esadecimale).

Visto che 0xE8 cade nel range U+0080 – U+07FF, servono 2 byte:

Template: 110xxxxx 10xxxxxx
││
0xE8 in binario = 11101000
│││││││
Dividi gli 11 bit: 00011 101000
↓↓↓↓↓ ↓↓↓↓↓↓
Risultato: 110_00011 10_101000
= 0xC3 = 0xA8

Quindi è in UTF-8 è: **0xC3 0xA8** (2 byte).

Come il tuo codice gestisce UTF-8

Il tuo progetto gestisce UTF-8 in tre punti chiave:

1. Lettura da tastiera (<tt>term.c</tt> → <tt>term_read_key</tt>)

// Se il byte letto è >= 0x80, è un carattere multi-byte
if(c >= 0x80){
int total = utf8_byte_length(c); // Quanti byte totali?
unsigned char buf[4];
buf[0] = c;
// Leggi i byte di continuazione
for(int i = 1; i < total; i++){
read(STDIN_FILENO, &buf[i], 1);
}
// Decodifica i byte in un singolo codepoint numerico
uint32_t cp;
utf8_decode((const char *)buf, &cp);
return (int)cp; // Restituisce il codepoint (es: 0xE8 per 'è')
}

Cosa succede quando premi è sulla tastiera:

  1. Il terminale invia 2 byte: 0xC3, 0xA8
  2. read() legge il primo byte 0xC3
  3. utf8_byte_length(0xC3) → 2 (perché 0xC3 inizia con 110...)
  4. Legge il secondo byte 0xA8
  5. utf8_decode() ricostruisce il codepoint: 0x00E8 (= 232)
  6. Restituisce 232 a main.c

2. Inserimento in una riga (<tt>rrow.c</tt> → <tt>rrow_insert_char</tt>)

void rrow_insert_char(Rrow row, int at, uint32_t codepoint){
// 1. Codifica il codepoint in byte UTF-8
char encoded[4];
int enc_len = utf8_encode(codepoint, encoded);
// Per 'è': encoded = {0xC3, 0xA8}, enc_len = 2
// 2. Converti la posizione cursore (in codepoints) in byte offset
size_t byte_off = utf8_byte_offset(row->chars, row->size, at);
// Se il cursore è dopo "café" (4 codepoints, 5 byte):
// at=4 → byte_off=5
// 3. Fai spazio per enc_len byte e copia
row->chars = realloc(row->chars, row->size + enc_len + 1);
memmove(&row->chars[byte_off + enc_len],
&row->chars[byte_off],
row->size - byte_off + 1);
memcpy(&row->chars[byte_off], encoded, enc_len);
row->size += enc_len;
}

Il punto cruciale: il cursore (c_x) conta i codepoints (caratteri visibili), ma l'array chars contiene byte. Ogni volta che devi operare sull'array, devi convertire con utf8_byte_offset().

3. Cancellazione di un carattere (<tt>rrow.c</tt> → <tt>rrow_del_char</tt>)

void rrow_del_char(Rrow row, int at){
// 1. Trova dove inizia il codepoint (in byte)
size_t byte_off = utf8_byte_offset(row->chars, row->size, at);
// 2. Quanti byte occupa questo codepoint?
int char_len = utf8_byte_length((uint8_t)row->chars[byte_off]);
// Per 'è': char_len = 2
// 3. Rimuovi quei byte
memmove(&row->chars[byte_off],
&row->chars[byte_off + char_len],
row->size - byte_off - char_len + 1);
row->size -= char_len;
}

Il concetto chiave: codepoint vs byte

Questa è la distinzione fondamentale da capire:

Stringa: c a f é (4 caratteri visibili)
Codepoints: [0] [1] [2] [3] (4 codepoints, c_x va da 0 a 4)
Byte: [0] [1] [2] [3][4] (5 byte, perché é ne usa 2)
c a f 0xC3 0xA8
  • **c_x lavora in codepoints** → per l'utente, il cursore è "dopo il 3° carattere"
  • **row->size e row->chars lavorano in byte** → per la memoria, devi sapere esattamente quanti byte spostare
  • Le funzioni utf8_byte_offset() e utf8_cp_index() fanno da ponte tra i due mondi

Tabella riassuntiva delle funzioni UTF-8

Funzione Input Output Quando la usi
utf8_byte_length(byte) Byte iniziale N° byte totali (1–4) Per sapere quanto è lungo un carattere
utf8_encode(cp, buf) Codepoint + buffer N° byte scritti Per scrivere un carattere in memoria
utf8_decode(str, &cp) Stringa UTF-8 Codepoint Per leggere un carattere dalla memoria

Trappole comuni con UTF-8

‍⚠️ 1. strlen() conta i BYTE, non i caratteri

strlen("café") == 5 // NON 4!

Usa utf8_codepoint_count() per contare i caratteri visibili.

‍⚠️ 2. Non puoi accedere al N-esimo carattere con str[n]

// SBAGLIATO: questo accede al 4° BYTE, non al 4° carattere
char c = "café"[3]; // c == 0xC3 (primo byte di 'é'), non 'é'!

Usa utf8_byte_offset() per trovare il byte corretto.

‍⚠️ 3. Non spezzare mai un carattere multi-byte a metà

Quando fai memmove o memcpy, assicurati di copiare/spostare TUTTI i byte di un codepoint. utf8_byte_length() ti dice quanti byte spostare.

‍⚠️ 4. Confronto tra stringhe UTF-8

Il confronto byte-a-byte (strcmp, memcmp) funziona correttamente per l'uguaglianza. Non funziona per l'ordinamento linguistico (es: ä vs z).
